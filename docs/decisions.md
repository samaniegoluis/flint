| D-017 | 2026-11-05 | **Vault file format v1.** Bytes 0-15 of the file are the Argon2id salt: libsodium generates it and SQLCipher stores it there through the raw key-and-salt form (`x'<key><salt>'`). Argon2id is pinned to ops 3, mem 256 MiB (numbers, not libsodium macros), and its output is the master key, which is what the keychain caches (keychain account `vault-<salt hex>`). `crypto_kdf` (context `flintvlt`) derives subkey 1, the SQLCipher page key (this refines D-014), and subkey 2, which seals secrets with XChaCha20-Poly1305 under the AAD `flint:v1:<table>:<id>:<field>`. The SQLCipher parameters (`cipher_compatibility` 4, page size 4096, HMAC/KDF SHA512, kdf_iter 256000) are applied on every open and recorded in `meta` by migration 001. Rollback journal, not WAL, so a cloud folder syncs one file | No auxiliary file and nothing else in clear; the salt is public by design and unique per vault, so it doubles as the keychain id. Pinned numbers keep old vaults openable across library upgrades. Subkeys give domain separation, so the page key and the secrets key are never the same bytes | A sidecar salt/params file (two files to sync); KDF params inside the encrypted DB (unreadable before unlock); the raw Argon2id output as page key (D-014 as written); WAL (extra `-wal`/`-shm` files in the synced folder) |
| D-018 | 2026-11-05 | **CLI contract.** Errors carry a stable code (`usage`, `not_found`, `conflict`, `locked`, `wrong_password`, `invalid`, `unsupported`, `keychain`, `io`, `internal`) with a fixed exit code each (2..10, `internal` = 1). With `--json`, the error goes to stderr as `{"error":{"code","message"}}`. Secrets (master password, host or credential passwords, private keys, passphrases) are read from the terminal with echo off, or from stdin with `--*-stdin` flags, never from argv or environment variables | Scripts and agents branch on codes, not on message text. Argv and the environment leak through `ps`, shell history and child processes | Free-text errors only; `--password <value>` flags; a `FLINT_PASSWORD` environment variable |
| D-019 | 2026-11-05 | **SSH in the CLI.** (1) Error codes `host_key`, `auth`, `network`, `timeout` are appended to D-018 as exit codes 11-14. (2) `connect` and `exec` exit with the remote status (a signal = 255), as `ssh` does; `--json` tells a remote status (object on stdout) from a Flint error (nothing on stdout, error on stderr). (3) Known host keys live in the vault (migration 002), one key per address (`host` on 22, `[host]:port` otherwise); an unknown key needs a terminal confirmation or `--accept-new-host-key`; a **changed key is always refused** until `known-host rm`. (4) Auth order: host key, host password, credential key, credential password, agent, then one typed password on a terminal. (5) Jump hosts are Flint's own direct-tcpip tunnels (socketpair + thread), one SSH session per hop, each verified and authenticated from its own vault entry | Scripts keep branching on codes 1-10 unchanged. Matching `ssh` makes `flint exec` a drop-in in scripts. Keys in the vault follow the vault across machines and stay encrypted. Refusing changed keys removes the one silent MITM path Tether's soft TOFU had. Own tunnels let every hop use vault credentials and Flint's known-host check, which libssh's ProxyJump callbacks would have split across a libssh thread | Soft TOFU (record and warn, Tether); `~/.ssh/known_hosts`; a fixed exit code for every exec with the remote status only in JSON; libssh `SSH_OPTIONS_PROXYJUMP` with callbacks; OpenSSH `ProxyCommand` |
