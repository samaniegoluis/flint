# Decisions

One line per decision that is expensive to reverse: date, the decision, why, what was
rejected. Append only. A reversal is a new line that names the one it supersedes.

| # | Date | Decision | Why | Rejected |
|---|---|---|---|---|
| D-001 | 2026-11-04 | Name the project **Flint** | A flint strikes fire, a nod to cfire and its author | Warden (agent-gatekeeper angle), Ember, Keystone |
| D-002 | 2026-11-04 | Write it in **cfire** with `ext:webui` | Dogfood the friend's language, feed back real gaps, release open source on top of it | Go + Wails (known-good), Rust + Tauri |
| D-003 | 2026-11-04 | **Hexagonal architecture**: core, ports, adapters, drivers | One core behind GUI, CLI and later MCP/agent/daemon. Native C++ shims swap out as cfire grows | GUI-centric layering (Tether) |
| D-004 | 2026-11-04 | Vault is **SQLite encrypted in full**, one file per vault, synced via any cloud folder | Keeps Tether's KeePass-style model and stops leaking host metadata to the cloud | Per-field encryption, a custom sync server |
| D-005 | 2026-11-04 | **Cache the derived key** (never the password) per vault in the OS keychain | Auto-unlock on known machines; proven in Tether | Remember the password; key file on disk |
| D-006 | 2026-11-04 | **Reopen the last vault on launch**; switch from an Obsidian-style vault switcher | Most launches want the same vault, so a picker every time is friction | Always show a vault picker |
| D-007 | 2026-11-04 | **macOS + Linux** for the MVP | `ext:webui` has no Windows backend (CF-001) | Waiting for Windows |
| D-008 | 2026-11-04 | **React + Vite + xterm.js** frontend, CSS Modules + tokens | Portable from Tether; Kitty keyboard protocol via pinned xterm.js beta | Svelte/Solid |
| D-009 | 2026-11-04 | Docs site with **Astro + Starlight** (landing + Docs), updated in the same commit as each feature | Docs stay fresh; ready for an open-source release | Docusaurus, VitePress, docs written at the end |
| D-010 | 2026-11-04 | **Lean workflow**: one MVP spec, a full roadmap, whole-milestone execution, owner checks only where a human is required | Modern agents move faster than phase-by-phase gating; nothing is lost because the roadmap holds the rest | Tether-era milestones → phases → manual tests |
| D-011 | 2026-11-05 | UI direction: **A (Editor)** base + B's command palette and unlock + C's in-pane session cards, with a **VS Code–style activity bar** (icon + label) where **Files (SFTP) is a sidebar view** that follows the active tab. Final set in `docs/design/` (`tokens.css` is the source of truth) | A's sidebar organises the vault best; Files in the sidebar keeps the terminal full-width and leaves the right side for the agent panel | B alone (hides the tree), C (relies on splits/workspaces, post-MVP), SFTP docked right of the terminal |
| D-012 | 2026-11-05 | SSH through **libssh** (LGPL-2.1), not libssh2 | Richer API for what Flint needs (PTY, key-by-content import, known_hosts helpers, agent, SFTP). Homebrew's libssh and SQLCipher share one libcrypto (openssl@4), while libssh2 pulls openssl@3, which would mean two libcryptos in one binary. LGPL is satisfied by dynamic linking (D-015) | libssh2 (BSD-3, smaller API, second OpenSSL) |
| D-013 | 2026-11-05 | Vault store on **SQLCipher** (system package) | Packaged on Homebrew and Debian/Ubuntu (`libsqlcipher-dev`), so `@pkg("sqlcipher")` resolves it with no vendored build. Encrypts the header, schema, rows and journal | SQLite3MultipleCiphers (not packaged; would need `build.CMake` vendoring) |
| D-014 | 2026-11-05 | The SQLCipher page key is a **raw 32-byte key from Argon2id** (libsodium), passed as `x'…'`, so SQLCipher's PBKDF2 is bypassed. Page encryption stays SQLCipher's own (AES-256-CBC + HMAC-SHA512 over OpenSSL) | Key derivation stays in libsodium. The page cipher is a vetted library, not hand-rolled. **Owner review (P4):** the page AEAD is not libsodium | Passing the password to SQLCipher (PBKDF2); per-field libsodium encryption (leaks metadata, D-004) |
| D-015 | 2026-11-05 | Native libraries (libssh, libsodium, SQLCipher) come from **system packages, resolved by pkg-config and linked dynamically** | Zero vendoring in the MVP, LGPL-clean, the same code on macOS (Homebrew) and Linux (apt). A distributable `.app` will need to bundle the dylibs (roadmap) | Vendored static builds via `build.CMake` (heavier, revisit for release packaging) |
| D-016 | 2026-11-05 | **Owner approves D-014 with a second layer.** P4 now reads: key derivation, and every AEAD that Flint itself performs, go through libsodium only. Whole-file page encryption is delegated to SQLCipher. From milestone 02: (1) secret values (passwords, private keys, passphrases) are additionally sealed with XChaCha20-Poly1305 under a subkey derived with libsodium `crypto_kdf`, and opened only at connect time; (2) the SQLCipher parameters (`cipher_compatibility = 4`, page size, KDF/HMAC settings) are pinned in the vault file format through a migration | Defence in depth: secrets stay under libsodium even if the SQLCipher layer failed. Pinned parameters keep old vaults openable when SQLCipher changes its defaults | A alone (no second layer); SQLite3MC ChaCha20 (still not libsodium); a whole-file blob (loses transactional writes); a custom libsodium VFS (hand-rolled scheme, violates P4) |
