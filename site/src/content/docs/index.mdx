## One vault, two ways in

The desktop app and the `flint` command are two front ends over the same core and the
same vault file. A host you add in one shows up in the other, with the same alias.

<AppShot />

<div class="flint-split">
<div>

### In a window

Tabs that split into up to four panes, each its own session, and a modern terminal
(xterm.js with the Kitty keyboard protocol; copy from Neovim,
tmux or Zellij on the server lands on your clipboard), a host tree with
nested groups, editors for hosts, keys and credentials with a connection test, a command
palette, and prompts for passwords and host keys. A host can open straight into `herdr`
or `tmux`. Read [The desktop app](/guides/desktop-app/).

</div>
<div>

### In a terminal

```sh
❯ flint host list
ALIAS    TARGET                GROUP    TAGS
bastion  jump@bastion.example  -        -
db       admin@10.0.0.12       prod     postgres
nas      pi@192.168.1.20       homelab  backup
web-01   deploy@10.0.0.5       prod     nginx
❯ flint connect db
```

</div>

## Files beside the terminal

The **Files** view (<kbd>⌘E</kbd>) browses the active tab's host over that tab's own
connection, with no second login. Upload, download, rename, delete and new folder; drag
files in from your computer; a queue with progress, cancel and retry; and a crosshair
that jumps to the terminal's current folder. **Copy to another server…** opens a second
pane on another host and copies from one to the other, host → Flint → host, with no key
or password put on either server. From a script, the same copies are
[`flint cp`](/guides/files/). Read [The Files view](/guides/files-view/).

## Tunnels to what only listens inside

A database or a panel bound to `localhost` on a server is one switch away. Save a tunnel
in the host (*Tunnels* in its editor), flip it on in the **Tunnels** view (<kbd>⇧⌘T</kbd>),
and `127.0.0.1:5432` on your machine reaches Postgres on `db`, over that host's login and
jump host from the vault: no `ssh -L`, no key on disk, never open to your network. Tick
*Open when I connect* and it starts with the host's tab, then outlives it. From a shell
it is the same tunnel:

```sh
flint tunnel add db pg --local 5432
flint tunnel up db:pg      # psql -h 127.0.0.1 -p 5432
```

Read [Tunnels](/guides/tunnels/).

## Built for scripts

Every command takes `--json`, and its exit codes are stable, so a shell script, a CI job
or an agent reads results instead of scraping text.

<div class="flint-split">
<div>

```sh
❯ flint exec web-01 --json -- uptime | jq .
{
  "host": "web-01",
  "exit_code": 0,
  "signal": "",
  "stdout": " 10:42:07 up 41 days,  2:17,  1 user,  load average: 0.08, 0.05, 0.01\n",
  "stderr": "",
  "duration_ms": 214
}
```

</div>
<div>

- **Errors as data.** With `--json`, a Flint error is a JSON object on stderr with a
  stable code; a remote exit status comes with its object on stdout.
- **No secrets in arguments.** Flint reads a secret from the terminal, with echo off, or
  from stdin. It never takes one from an argument or an environment variable, where it
  would leak into `ps` and shell history.
- **Jump hosts by alias.** `db` above is reached through `bastion`, a hop Flint verifies
  like any other host.
- **Files by alias.** `flint cp ./app.conf web-01:/etc/app/` copies over SFTP with the
  login in the vault, a folder with `-r`, and no key on disk for `scp`. Between two hosts
  too: `flint cp db-01:/backups/db.sql nas:/srv/` passes through Flint, so no key ever
  lands on a host.

See the [CLI reference](/reference/cli/).

</div>
</div>

## Secure by default

<CardGrid>
	<Card title="The whole file is encrypted" icon="seti:lock">
		Hostnames, users, notes and known host keys are encrypted too, not only passwords
		(SQLCipher, AES-256). Put the vault in any cloud-synced folder.
	</Card>
	<Card title="Secrets sealed twice" icon="approve-check">
		Passwords, private keys and passphrases are sealed again with XChaCha20-Poly1305,
		each bound to its own field, and opened only to connect.
	</Card>
	<Card title="Flint holds the key" icon="laptop">
		The vault key comes from Argon2id and lives in the running app. The CLI and your
		agents ask the app, which runs nothing for a program you have not allowed; it locks
		on its own when you are idle, the screen locks or the computer sleeps. Closed to the
		menu bar, it keeps serving them with its window locked.
	</Card>
	<Card title="Host keys are checked" icon="warning">
		Flint asks before it trusts a new server key, and always refuses a changed one
		before any credential is sent.
	</Card>
</CardGrid>

The details are in [Vault format](/reference/vault-format/),
[Connecting](/guides/connecting/#known-hosts) and the [Security model](/reference/security-model/),
which also says what an unlocked vault does not protect against.
