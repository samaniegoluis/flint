# Contributing

Flint is designed, written and maintained by one person. That keeps its design consistent
and the project sustainable, and it shapes how you can help.

## Bug reports are welcome

[Open a bug report](https://github.com/samaniegoluis/flint/issues/new?template=bug.yml)
with what you did, what you expected, what happened, your OS and the output of
`flint --version`. A short, exact reproduction helps more than anything else.

Never paste a password, a private key, a token or your vault file into an issue. For a
security problem, do not open an issue at all: see [SECURITY.md](SECURITY.md).

## Ideas are welcome

[Suggest an idea](https://github.com/samaniegoluis/flint/issues/new?template=idea.yml) as
an issue too: the problem you have first, then what you would like Flint to do. I read
them all; I cannot promise to build them. What fits goes into the [roadmap](ROADMAP.md).

## Pull requests are not accepted

Only the repository's collaborators can open pull requests. This is not about the quality
of your code: one author keeps the design in one head and the copyright in one place. If
you found a fix, describe it in an issue, with the patch inline if you like, and I will
implement it.

You are free to fork Flint under its [licence](LICENSE).

Thank you for using Flint.
